# 投稿与审稿工作流 · 安装与使用

本工作流面向已有稿件的人文社科作者，提供材料核实、初稿诊断、改稿、期刊要求核对、投稿包整理、审稿意见决策和返修回复七个方法。导航见 [主库 README](../../README.md)。

## 安装

和本库其他 skill 一样全局安装（见 [主库 README](../../README.md) 的「安装」；用 POPPER AI学术工作站的学员在「AI学术环境配置 → 课程 skills → 交给 AI 安装」）。七个目录要一起装，并保留全部 `references/`：六个业务方法先读取装在同一个 skills 文件夹里的 `submission-task-intake`，各自还读取 `references/source-basis.md`；质性诊断另读 `manuscript-diagnosis/references/qualitative-criteria.md`。不要只复制单个 `SKILL.md`。

论文项目里另有 `skills/<名字>/SKILL.md`（比如自己改过的定制版）时，以项目那份为准。

首次调用可对执行 AI 说：

> 先核实我的论文项目根目录，实际读取 submission-task-intake 和本次业务场景的 skill 及其支持文件，再按我的材料和已批准范围执行。若输入、版本或批准记录有缺项，按方法规则说明受影响步骤。

## 入口与交接

- **初稿改稿**：共用核实 → 初稿诊断 → 作者决定问题与修改范围 → 批准范围内改稿 → 作者确认稿件。
- **投稿准备**：共用核实 → 指定期刊要求核对 → 作者确认适用要求 → 投稿包整理 → 作者终审。
- **返修**：共用核实 → 审稿意见台账与回应建议 → 作者逐项决定 → 实际返修 → 据修订稿撰写回复 → 作者确认 → 期刊要求复核 → 返修包整理。

可从当前实际阶段进入，已有有效登记与明确决定按方法规则复用。AI 建议、最新轮次或材料路径存在均不能代替作者批准与实际读取。

期刊初稿或综述文章工作流的产出可作为基准稿输入，需明确具体文件、版本与确认记录。业务结果写入论文项目的 `写作/投稿/`（项目说明另有约定的以项目为准），多轮使用下一空闲 `-R<n>`，日志写入 `写作/投稿/分析日志.md`。本 skill 库只保存方法。

项目中的 `AGENTS.md`、`CLAUDE.md` 和 `投稿与审稿规范.md` 指使用者自己的规则文件（`投稿与审稿规范.md` 有才读，没有不算缺项）。缺少时如实说明，依据方法的缺项规则处理；支持文件中的旧项目文件名只说明历史来源，不要求复制原作者的完整项目指令，也不能据文件名脑补内容。
